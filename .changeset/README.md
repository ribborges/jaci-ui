# Changesets

The initial `0.1.0` release is the baseline for the public package. Historical Changesets from
the pre-release implementation were intentionally consumed before publishing so the first
release does not immediately generate a misleading `0.2.0`.

Add a Changeset for every subsequent user-visible package change. Documentation-only and
internal automation changes do not need one. Use `patch` for fixes, `minor` for backwards-
compatible features, and `major` for breaking changes.
